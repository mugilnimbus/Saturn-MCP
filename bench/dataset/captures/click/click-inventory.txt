docs/parameter-types.md:20:(choice-opts)=
docs/parameter-types.md:22:### Choice
docs/parameter-types.md:24:Sometimes, you want to have a parameter be a choice of a list of values. In that case you can use {class}`Choice` type.
docs/parameter-types.md:25:It can be instantiated with a list of valid values. The originally passed choice will be returned, not the str passed on
docs/parameter-types.md:26:the command line. Token normalization functions and `case_sensitive=False` can cause the two to be different but still
docs/parameter-types.md:27:match. {meth}`Choice.normalize_choice` for more info.
docs/parameter-types.md:30:Example:
docs/parameter-types.md:32:```{eval-rst}
docs/parameter-types.md:33:.. click:example::
docs/parameter-types.md:35:    import enum
docs/parameter-types.md:37:    class HashType(enum.Enum):
docs/parameter-types.md:38:        MD5 = enum.auto()
docs/parameter-types.md:39:        SHA1 = enum.auto()
docs/parameter-types.md:41:    @click.command()
docs/parameter-types.md:42:    @click.option('--hash-type',
docs/parameter-types.md:43:                  type=click.Choice(HashType, case_sensitive=False))
docs/parameter-types.md:44:    def digest(hash_type: HashType):
docs/parameter-types.md:45:        click.echo(hash_type)
docs/parameter-types.md:47:What it looks like:
docs/parameter-types.md:49:.. click:run::
docs/parameter-types.md:51:    invoke(digest, args=['--hash-type=MD5'])
docs/parameter-types.md:52:    println()
docs/parameter-types.md:53:    invoke(digest, args=['--hash-type=md5'])
docs/parameter-types.md:54:    println()
docs/parameter-types.md:55:    invoke(digest, args=['--hash-type=foo'])
docs/parameter-types.md:56:    println()
docs/parameter-types.md:57:    invoke(digest, args=['--help'])
docs/parameter-types.md:58:```
docs/parameter-types.md:60:Any iterable may be passed to {class}`Choice`. If an `Enum` is passed, the names of the enum members will be used as
docs/parameter-types.md:61:valid choices.
docs/parameter-types.md:63:Choices work with options that have `multiple=True`. If a `default` value is given with `multiple=True`, it should be a
docs/parameter-types.md:64:list or tuple of valid choices.
docs/parameter-types.md:66:Choices should be unique after normalization, see {meth}`Choice.normalize_choice` for more info.
docs/parameter-types.md:68:```{versionchanged} 7.1
docs/parameter-types.md:69:The resulting value from an option will always be one of the originally passed choices
docs/parameter-types.md:70:regardless of `case_sensitive`.
docs/parameter-types.md:71:```
docs/parameter-types.md:73:```{versionchanged} 8.4.0
docs/parameter-types.md:74:{class}`Choice` is now generic. Parameterize it with the choice value type
docs/parameter-types.md:75:({class}`!Choice[HashType]` for an enum, {class}`!Choice[str]` for plain

docs/parameter-types.md:79:(ranges)=
docs/parameter-types.md:81:### Int and Float Ranges
docs/parameter-types.md:83:The {class}`IntRange` type extends the {data}`INT` type to ensure the value is contained in the given range. The
docs/parameter-types.md:84:{class}`FloatRange` type does the same for {data}`FLOAT`.
docs/parameter-types.md:86:If `min` or `max` is omitted, that side is *unbounded*. Any value in that direction is accepted. By default, both bounds
docs/parameter-types.md:87:are *closed*, which means the boundary value is included in the accepted range. `min_open` and `max_open` can be used to
docs/parameter-types.md:88:exclude that boundary from the range.
docs/parameter-types.md:90:If `clamp` mode is enabled, a value that is outside the range is set to the boundary instead of failing. For example,
docs/parameter-types.md:91:the range `0, 5` would return `5` for the value `10`, or `0` for the value `-1`. When using {class}`FloatRange`, `clamp`
docs/parameter-types.md:92:can only be enabled if both bounds are *closed* (the default).
docs/parameter-types.md:94:```{eval-rst}
docs/parameter-types.md:95:.. click:example::
docs/parameter-types.md:97:    @click.command()
docs/parameter-types.md:98:    @click.option("--count", type=click.IntRange(0, 20, clamp=True))
docs/parameter-types.md:99:    @click.option("--digit", type=click.IntRange(0, 9))
docs/parameter-types.md:100:    def repeat(count, digit):
docs/parameter-types.md:101:        click.echo(str(digit) * count)
docs/parameter-types.md:103:.. click:run::
docs/parameter-types.md:105:    invoke(repeat, args=['--count=100', '--digit=5'])
docs/parameter-types.md:106:    invoke(repeat, args=['--count=6', '--digit=12'])
docs/parameter-types.md:107:```
docs/parameter-types.md:109:## Built-in Types Listing
docs/parameter-types.md:111:The supported parameter {ref}`click-api-types` are
docs/parameter-types.md:113:- `str` / {data}`click.STRING`: The default parameter type which indicates unicode strings.
docs/parameter-types.md:115:- `int` / {data}`click.INT`: A parameter that only accepts integers.
docs/parameter-types.md:117:- `float` / {data}`click.FLOAT`: A parameter that only accepts floating point values.
docs/parameter-types.md:119:- `bool` / {data}`click.BOOL`: A parameter that accepts boolean values. This is automatically used for boolean flags.
docs/parameter-types.md:120:  The string values "1", "true", "t", "yes", "y", and "on" convert to `True`. "0", "false", "f", "no", "n", and "off"
docs/parameter-types.md:121:  convert to `False`.
docs/parameter-types.md:123:- {data}`click.UUID`: A parameter that accepts UUID values. This is not automatically guessed but represented as
docs/parameter-types.md:124:  {class}`uuid.UUID`.

docs/parameter-types.md:156:(type-inference)=
docs/parameter-types.md:158:## How Click Infers a Type
docs/parameter-types.md:160:When `type` is not given, Click infers it from `default`. Only the defaults listed below
docs/parameter-types.md:161:are recognized. Every other default gives {data}`STRING`.
docs/parameter-types.md:163:| `default`                                        | Inferred type                                   |
docs/parameter-types.md:164:| ------------------------------------------------ | ----------------------------------------------- |
docs/parameter-types.md:165:| not given, or `None`                             | {data}`STRING`                                  |
docs/parameter-types.md:166:| `"git"`                                          | {data}`STRING`                                  |
docs/parameter-types.md:167:| `5`                                              | {data}`INT`                                     |
docs/parameter-types.md:168:| `1.5`                                            | {data}`FLOAT`                                   |
docs/parameter-types.md:169:| `True`                                           | {data}`BOOL`                                    |
docs/parameter-types.md:170:| `[]` or `()`                                     | {data}`STRING`                                  |
docs/parameter-types.md:171:| `[1, 2]` or `(1, 2)`                             | {data}`INT`                                     |
docs/parameter-types.md:172:| `[1.5, 2.5]`                                     | {data}`FLOAT`                                   |
docs/parameter-types.md:173:| `[1, "git"]`                                     | {data}`INT`                                     |
docs/parameter-types.md:174:| `[(1, "git")]`                                   | {class}`Tuple` of ({data}`INT`, {data}`STRING`) |
docs/parameter-types.md:175:| `{1, 2}` or `frozenset({1, 2})`                  | {data}`STRING`                                  |
docs/parameter-types.md:176:| `{"a": 1}`                                       | {data}`STRING`                                  |
docs/parameter-types.md:177:| {class}`uuid.UUID` or {class}`datetime.datetime` | {data}`STRING`                                  |
docs/parameter-types.md:178:| `b"git"`, or any other object                    | {data}`STRING`                                  |
docs/parameter-types.md:180:A `list` or `tuple` gives the type of its **first item only**, so `[1, "git"]` gives
docs/parameter-types.md:181:{data}`INT` and the second item is converted with it. A first item that is itself a
docs/parameter-types.md:182:`list` or `tuple` gives a {class}`Tuple`, which also sets `nargs`.
docs/parameter-types.md:184:A `set`, a `frozenset`, a `dict`, and a type Click ships but does not guess, such as
docs/parameter-types.md:185:{class}`uuid.UUID`, all land in the last group. Their default is converted with
docs/parameter-types.md:186:{data}`STRING`, so the command receives the `str()` form of the value.
docs/parameter-types.md:188:```{eval-rst}
docs/parameter-types.md:189:.. click:example::
docs/parameter-types.md:191:    @click.command()
docs/parameter-types.md:192:    @click.option('--count', default=5)
docs/parameter-types.md:193:    @click.option('--tag', default={'git'})
docs/parameter-types.md:194:    def show(count, tag):
docs/parameter-types.md:195:        click.echo(f"count is {type(count).__name__}, tag is {type(tag).__name__}")
docs/parameter-types.md:197:.. click:run::
docs/parameter-types.md:199:    invoke(show, args=[])
docs/parameter-types.md:200:```
docs/parameter-types.md:202:When `type` is given a callable Click does not recognize, that callable is called on the
docs/parameter-types.md:203:string coming from the command line, and a `ValueError` it raises is reported as a bad
docs/parameter-types.md:204:parameter. A container is rarely useful there, because calling it on a string splits the
docs/parameter-types.md:205:string: `set` turns `"git"` into `{"g", "i", "t"}`. Pass a {class}`ParamType` instead,
docs/parameter-types.md:206:as described in [](#how-to-implement-custom-types).
docs/parameter-types.md:208:## How to Implement Custom Types
docs/parameter-types.md:210:To implement a custom type, you need to subclass the {class}`ParamType` class. For simple cases, passing a Python
docs/parameter-types.md:211:function that fails with a `ValueError` is also supported, though discouraged. Override the {meth}`~ParamType.convert`
docs/parameter-types.md:212:method to convert the value from a string to the correct type.
docs/parameter-types.md:214:{class}`ParamType` is generic in the converted value type: parameterize it with
docs/parameter-types.md:215:the type returned by `convert` so that consumers (and type checkers) can rely
docs/parameter-types.md:216:on the narrowed return type.
docs/parameter-types.md:218:The following code implements an integer type that accepts hex and octal numbers in addition to normal integers, and
docs/parameter-types.md:219:converts them into regular integers.
docs/parameter-types.md:221:```python
docs/parameter-types.md:222:import click
docs/parameter-types.md:225:class BasedIntParamType(click.ParamType[int]):
docs/parameter-types.md:226:    name = "integer"
docs/parameter-types.md:228:    def convert(self, value, param, ctx) -> int:
docs/parameter-types.md:229:        if isinstance(value, int):
docs/parameter-types.md:230:            return value
docs/parameter-types.md:232:        try:
docs/parameter-types.md:233:            if value[:2].lower() == "0x":
docs/parameter-types.md:234:                return int(value[2:], 16)
docs/parameter-types.md:235:            elif value[:1] == "0":
docs/parameter-types.md:236:                return int(value, 8)
docs/parameter-types.md:237:            return int(value, 10)
docs/parameter-types.md:238:        except ValueError:
docs/parameter-types.md:239:            self.fail(f"{value!r} is not a valid integer", param, ctx)
docs/parameter-types.md:242:BASED_INT = BasedIntParamType()
docs/parameter-types.md:243:```
docs/parameter-types.md:245:The {attr}`~ParamType.name` attribute is optional and is used for documentation. Call {meth}`~ParamType.fail` if
docs/parameter-types.md:246:conversion fails. The `param` and `ctx` arguments may be `None` in some cases such as prompts.
docs/parameter-types.md:248:Values from user input or the command line will be strings, but default values and Python arguments may already be the
docs/parameter-types.md:249:correct type. The custom type should check at the top if the value is already valid and pass it through to support those
docs/parameter-types.md:250:cases.
docs/parameter-types.md:252:```{versionchanged} 8.4.0
docs/parameter-types.md:253:{class}`ParamType` is now a generic abstract base class. Parameterize it with
docs/parameter-types.md:254:the converted value type ({class}`!ParamType[int]` for an integer-returning
docs/parameter-types.md:255:type) so that {meth}`~ParamType.convert` and downstream consumers carry the
docs/parameter-types.md:256:narrowed type.
