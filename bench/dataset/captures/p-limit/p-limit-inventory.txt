readme.md:78:### limit.map(iterable, mapperFunction)
readme.md:80:Process an iterable of inputs with limited concurrency.
readme.md:82:The mapper function receives the item value and its index.
readme.md:84:Returns a promise equivalent to `Promise.all(Array.from(iterable, (item, index) => limit(mapperFunction, item, index)))`.
readme.md:86:If the iterable throws during iteration, the returned promise rejects with that error. Mapper functions that were already scheduled still run, and their results are discarded.
readme.md:88:This is a convenience function for processing inputs that arrive in batches. For more complex use cases, see [p-map](https://github.com/sindresorhus/p-map).
readme.md:90:### limit.activeCount
readme.md:92:The number of promises that are currently running.
readme.md:94:### limit.pendingCount
readme.md:96:The number of promises that are waiting to run (i.e. their internal `fn` was not called yet).
readme.md:98:### limit.clearQueue()
readme.md:100:Discard pending promises that are waiting to run.
readme.md:102:This might be useful if you want to tear down the queue at the end of your program's lifecycle or discard any function calls referencing an intermediary state of your app.
readme.md:104:Note: This does not cancel promises that are already running.
readme.md:106:When `rejectOnClear` is enabled, pending promises are rejected with an `AbortError`.
readme.md:107:This is recommended if you await the returned promises, for example with `Promise.all`, so pending tasks do not remain unresolved after `clearQueue()`.
readme.md:109:### limit.concurrency
readme.md:111:Get or set the concurrency limit.
readme.md:113:### limitFunction(fn, options) <sup>named export</sup>
readme.md:115:Returns a function with limited concurrency.
readme.md:117:The returned function manages its own concurrent executions, allowing you to call it multiple times without exceeding the specified concurrency limit.
readme.md:119:Ideal for scenarios where you need to control the number of simultaneous executions of a single function, rather than managing concurrency across multiple functions.
