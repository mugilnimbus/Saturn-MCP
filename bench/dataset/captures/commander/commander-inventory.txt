Readme.md:176:## Options
Readme.md:178:Options are defined with the `.option()` method, also serving as documentation for the options. Each option can have a short flag (single character) and a long name, separated by a comma, a space, or a vertical bar (`|`). To allow a wider range of short-ish flags than just single characters, you may also have two long options.
Readme.md:180:```js
Readme.md:181:program
Readme.md:182:  .option('-p, --port <number>', 'server port number')
Readme.md:183:  .option('--trace', 'add extra debugging output')
Readme.md:184:  .option('--ws, --workspace <name>', 'use a custom workspace')
Readme.md:185:```
Readme.md:187:The parsed options can be accessed by calling `.opts()` on a `Command` object, and are passed to the action handler.
Readme.md:189:Multi-word options like `--template-engine` are normalized to camelCase option names, resulting in properties such as `program.opts().templateEngine`.
Readme.md:191:An option and its option-argument can be separated by a space, or combined into the same argument. The option-argument can follow the short option directly, or follow an `=` for a long option.
Readme.md:193:```sh
Readme.md:194:serve -p 80
Readme.md:195:serve -p80
Readme.md:196:serve --port 80
Readme.md:197:serve --port=80
Readme.md:198:```
Readme.md:200:You can use `--` to indicate the end of the options, and any remaining arguments will be used without being interpreted.
Readme.md:202:By default, options on the command line are not positional, and can be specified before or after other arguments.
Readme.md:204:There are additional related routines for when `.opts()` is not enough:
Readme.md:206:- `.optsWithGlobals()` returns merged local and global option values
Readme.md:207:- `.getOptionValue()` and `.setOptionValue()` work with a single option value
Readme.md:208:- `.getOptionValueSource()` and `.setOptionValueWithSource()` include where the option value came from

Readme.md:519:## Commands
Readme.md:521:You can specify (sub)commands using `.command()` or `.addCommand()`. There are two ways these can be implemented: using an `.action()` handler attached to the command; or as a stand-alone executable file. (More detail about this later.)
Readme.md:523:Subcommands may be nested. Example file: [nestedCommands.js](./examples/nestedCommands.js).
Readme.md:525:In the first parameter to `.command()` you specify the command name. You may append the command-arguments after the command name, or specify them separately using `.argument()`. The arguments may be `<required>` or `[optional]`, and the last argument may also be `variadic...`.
Readme.md:527:You can use `.addCommand()` to add an already configured subcommand to the program.
Readme.md:529:For example:
Readme.md:531:```js
Readme.md:532:// Command implemented using action handler (description is supplied separately to `.command`)
Readme.md:533:// Returns new command for configuring.
Readme.md:534:program
Readme.md:535:  .command('clone <source> [destination]')
Readme.md:536:  .description('clone a repository into a newly created directory')
Readme.md:537:  .action((source, destination) => {
Readme.md:538:    console.log('clone command called');
Readme.md:539:  });
Readme.md:541:// Command implemented using stand-alone executable file, indicated by adding description as second parameter to `.command`.
Readme.md:542:// Returns `this` for adding more commands.
Readme.md:543:program
Readme.md:544:  .command('start <service>', 'start named service')
Readme.md:545:  .command('stop [service]', 'stop named service, or all if no name supplied');
Readme.md:547:// Command prepared separately.
Readme.md:548:// Returns `this` for adding more commands.
Readme.md:549:program
Readme.md:550:  .addCommand(build.makeBuildCommand());
Readme.md:551:```
Readme.md:553:Configuration options can be passed with the call to `.command()` and `.addCommand()`. Specifying `hidden: true` will
Readme.md:554:remove the command from the generated help output. Specifying `isDefault: true` will run the subcommand if no other
Readme.md:555:subcommand is specified. (Example file: [defaultCommand.js](./examples/defaultCommand.js).)
Readme.md:557:You can add alternative names for a command with `.alias()`. (Example file: [alias.cjs](./examples/alias.cjs).)
Readme.md:559:`.command()` automatically copies the inherited settings from the parent command to the newly created subcommand. This is only done during creation; any later setting changes to the parent are not inherited.
Readme.md:561:For safety, `.addCommand()` does not automatically copy the inherited settings from the parent command. There is a helper routine `.copyInheritedSettings()` for copying the settings when they are wanted.
Readme.md:563:### Command-arguments
Readme.md:565:For subcommands, you can specify the argument syntax in the call to `.command()` (as shown above). This
Readme.md:566:is the only method usable for subcommands implemented using a stand-alone executable.
Readme.md:568:Alternatively, you can instead use the following method. To configure a command, you can use `.argument()` to specify each expected command-argument.
Readme.md:569:You supply the argument name and an optional description. The argument may be `<required>` or `[optional]`.
Readme.md:570:You can specify a default value for an optional command-argument.
Readme.md:572:Example file: [argument.js](./examples/argument.js)
Readme.md:574:```js
Readme.md:575:program
Readme.md:576:  .version('0.1.0')
Readme.md:577:  .argument('<username>', 'user to login')
Readme.md:578:  .argument('[password]', 'password for user, if required', 'no password given')
Readme.md:579:  .action((username, password) => {
Readme.md:580:    console.log('username:', username);
Readme.md:581:    console.log('password:', password);
Readme.md:582:  });
Readme.md:583:```
Readme.md:585:The last argument of a command can be variadic, and _only_ the last argument.  To make an argument variadic, simply
Readme.md:586:append `...` to the argument name.
Readme.md:588:A variadic argument is passed to the action handler as an array.

Readme.md:964:### .parse() and .parseAsync()
Readme.md:966:Call with no parameters to parse `process.argv`. Detects Electron and special node options like `node --eval`. Easy mode!

Readme.md:984:### Parsing Configuration
Readme.md:986:If the default parsing does not suit your needs, there are some behaviours to support other usage patterns.
Readme.md:988:By default, program options are recognised before and after subcommands. To only look for program options before subcommands, use `.enablePositionalOptions()`. This lets you use
Readme.md:989:an option for a different purpose in subcommands.
Readme.md:991:Example file: [positional-options.js](./examples/positional-options.js)
Readme.md:993:With positional options, the `-b` is a program option in the first line and a subcommand option in the second line:
Readme.md:995:```sh
Readme.md:996:program -b subcommand
Readme.md:997:program subcommand -b
Readme.md:998:```
Readme.md:1000:By default, options are recognised before and after command-arguments. To only process options that come
Readme.md:1001:before the command-arguments, use `.passThroughOptions()`. This lets you pass the arguments and following options through to another program
Readme.md:1002:without needing to use `--` to end the option processing.
Readme.md:1003:To use pass through options in a subcommand, the program needs to enable positional options.
Readme.md:1005:Example file: [pass-through-options.js](./examples/pass-through-options.js)
Readme.md:1007:With pass through options, the `--port=80` is a program option in the first line and passed through as a command-argument in the second line:
Readme.md:1009:```sh
Readme.md:1010:program --port=80 arg
Readme.md:1011:program arg --port=80
Readme.md:1012:```
Readme.md:1014:By default, the option processing shows an error for an unknown option. To have an unknown option treated as an ordinary command-argument and continue looking for options, use `.allowUnknownOption()`. This lets you mix known and unknown options.
Readme.md:1016:By default, the argument processing displays an error for more command-arguments than expected.
Readme.md:1017:To suppress the error for excess arguments, use `.allowExcessArguments()`.

Readme.md:1106:### Override exit and output handling
Readme.md:1108:By default, Commander calls `process.exit()` when it detects errors, or after displaying the help or version. You can override
Readme.md:1109:this behaviour and optionally supply a callback. The default override throws a `CommanderError`.
Readme.md:1111:The override callback is passed a `CommanderError` with the properties:
Readme.md:1112:- `exitCode`: number
Readme.md:1113:- `code`: string 
Readme.md:1114:- `message`: string
Readme.md:1116:Commander expects the callback to terminate the normal program flow, and will call `process.exit()` if the callback returns.
Readme.md:1117:The normal display of error messages or version or help is not affected by the override, which is called after the display.
Readme.md:1119:```js
Readme.md:1120:program.exitOverride();
Readme.md:1122:try {
Readme.md:1123:  program.parse(process.argv);
Readme.md:1124:} catch (err) {
Readme.md:1125:  // custom processing...
Readme.md:1126:}
Readme.md:1127:```
Readme.md:1129:By default, Commander is configured for a command-line application and writes to stdout and stderr.
Readme.md:1130:You can modify this behaviour for custom applications. In addition, you can modify the display of error messages.
Readme.md:1132:Example file: [configure-output.js](./examples/configure-output.js)
Readme.md:1134:```js
