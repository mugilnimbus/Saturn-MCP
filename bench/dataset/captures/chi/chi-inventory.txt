README.md:6:`chi` is a lightweight, idiomatic and composable router for building Go HTTP services. It's
README.md:7:especially good at helping you write large REST API services that are kept maintainable as your
README.md:8:project grows and changes. `chi` is built on the new `context` package introduced in Go 1.7 to
README.md:9:handle signaling, cancelation and request-scoped values across a handler chain.
README.md:11:The focus of the project has been to seek out an elegant and comfortable design for writing
README.md:12:REST API servers, written during the development of the Pressly API service that powers our
README.md:13:public API service, which in turn powers all of our client-side applications.
README.md:15:The key considerations of chi's design are: project structure, maintainability, standard http
README.md:16:handlers (stdlib-only), developer productivity, and deconstructing a large system into many small
README.md:17:parts. The core router `github.com/go-chi/chi` is quite small (less than 1000 LOC), but we've also
README.md:18:included some useful/optional subpackages: [middleware](/middleware), [render](https://github.com/go-chi/render)
README.md:19:and [docgen](https://github.com/go-chi/docgen). We hope you enjoy it too!

README.md:193:	With(middlewares ...func(http.Handler) http.Handler) Router

README.md:196:	// path, with a fresh middleware stack for the inline-Router.

README.md:258:### Middleware handlers
README.md:260:chi's middlewares are just stdlib net/http middleware handlers. There is nothing special
README.md:261:about them, which means the router and all the tooling is designed to be compatible and
README.md:262:friendly with any middleware in the community. This offers much better extensibility and reuse
README.md:263:of packages and is at the heart of chi's purpose.

README.md:266:the value of `"123"`. This middleware sets a hypothetical user identifier on the request
README.md:267:context and calls the next handler in the chain.

README.md:418:### Choosing a ClientIP middleware
README.md:420:The legacy [RealIP] middleware is deprecated — it is vulnerable to IP spoofing
README.md:421:(GHSA-3fxj-6jh8-hvhx, GHSA-rjr7-jggh-pgcp, GHSA-9g5q-2w5x-hmxf) and mutates
README.md:422:`r.RemoteAddr`. Use one of the four `ClientIPFrom*` middlewares instead — pick
README.md:423:exactly one based on your network setup — and read the resulting IP with
README.md:424:[GetClientIP] (string) or [GetClientIPAddr] (`netip.Addr`):
README.md:426:| Your setup | Use |
README.md:427:|---|---|
README.md:428:| Directly on the public internet, no proxy | `middleware.ClientIPFromRemoteAddr` |
README.md:429:| Behind nginx (`X-Real-IP`), Cloudflare (`CF-Connecting-IP`), Apache (`X-Client-IP`) | `middleware.ClientIPFromHeader("<your-trusted-header>")` |
README.md:430:| Behind one or more proxies whose IP ranges you can list | `middleware.ClientIPFromXFF("10.0.0.0/8", ...)` |
README.md:431:| Behind a known, fixed number of proxies with dynamic IPs | `middleware.ClientIPFromXFFTrustedProxies(2)` |
README.md:433:```go
README.md:434:r := chi.NewRouter()
README.md:435:r.Use(middleware.RequestID)
README.md:437:// Pick exactly one. Examples for common deployments:
README.md:439:// Direct internet exposure (no proxy):
README.md:440:// r.Use(middleware.ClientIPFromRemoteAddr)
README.md:442:// Behind Cloudflare:
README.md:443:// r.Use(middleware.ClientIPFromHeader("CF-Connecting-IP"))
README.md:445:// Behind AWS CloudFront (or any proxy fleet with known CIDRs):
README.md:446:r.Use(middleware.ClientIPFromXFF(
README.md:447:    "13.32.0.0/15",   // CloudFront IPv4
README.md:448:    "52.46.0.0/18",   // CloudFront IPv4
README.md:449:    "2600:9000::/28", // CloudFront IPv6
README.md:450:))
README.md:452:// Behind a known number of proxies with dynamic IPs:
README.md:453:// r.Use(middleware.ClientIPFromXFFTrustedProxies(2))
README.md:455:r.Use(middleware.Logger)
README.md:456:r.Use(middleware.Recoverer)
README.md:458:r.Get("/", func(w http.ResponseWriter, r *http.Request) {
README.md:459:    clientIP := middleware.GetClientIP(r.Context()) // for logs, rate-limit keys, etc.
README.md:460:    _ = clientIP
README.md:461:})
README.md:462:```
README.md:464:These middlewares never mutate `r.RemoteAddr`. They store a normalized
README.md:465:`netip.Addr` in the request context — IPv4-mapped IPv6 (`::ffff:a.b.c.d`)
README.md:466:is folded to plain IPv4, and IPv6 zone identifiers carried in headers are
README.md:467:stripped, so one logical client maps to a single canonical key for logs,
README.md:468:rate limits, and ACLs.
README.md:470:For `ClientIPFromXFFTrustedProxies`, `numTrustedProxies` is the total proxy
README.md:471:hops between client and server. Prefer `ClientIPFromXFF` with explicit CIDRs
README.md:472:when you can — CIDR-based trust cannot off-by-one. See the godoc for a
README.md:473:deployment recipe and a verify checklist.
README.md:475:See the per-function godoc for the full semantics of each middleware, and
README.md:476:[adam-p's "The perils of the 'real' client IP"](https://adam-p.ca/blog/2022/03/x-forwarded-for/)
README.md:477:for the underlying threat model.
README.md:479:### Deprecating and removing a route
README.md:481:Use `Deprecation` first. Add `Sunset` when you know the removal date.
README.md:483:| Situation                                                | Use                         |
README.md:484:| :------------------------------------------------------- | :-------------------------- |
README.md:485:| Route works, clients should migrate, no removal date yet | `Deprecation`               |
README.md:486:| You know the date the route will stop working            | `Deprecation` + `Sunset`    |
README.md:487:| Route is already removed                                 | Neither. Return `410 Gone`. |
README.md:489:```go
README.md:490:// A bad date parses to the zero time, and the middleware panics at startup.
README.md:491:deprecatedAt, _ := time.Parse(time.DateOnly, "2026-01-15")
README.md:492:sunsetAt, _ := time.Parse(time.DateOnly, "2026-07-01")
README.md:494:// Step 1: the route is deprecated.
README.md:495:r.With(middleware.Deprecation(deprecatedAt)).Get("/v1/users", listUsers)
README.md:497:// Step 2: the removal date is known.
README.md:498:r.With(middleware.Deprecation(deprecatedAt), middleware.Sunset(sunsetAt)).Get("/v1/users", listUsers)
README.md:500:// After sunsetAt: remove the route, or return 410 Gone.
README.md:501:```
